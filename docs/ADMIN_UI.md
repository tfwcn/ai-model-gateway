# 🖥️ 管理台前端

`/admin/ui/` 是一个纯静态管理页：看用量与性能、下钻审计明细、**编辑模型配置**（不用再手改 `models.yaml`）。

它不是独立服务，只是 `/admin/*` 接口的另一个客户端：所有数据与校验都来自后端，前端只负责呈现和把改动翻译成补丁操作。

## 怎么打开

```text
http://<网关地址>:<端口>/admin/ui/
```

打开后在右上角输入 `GATEWAY_API_KEY` 并点「连接」。密钥只存在浏览器 `sessionStorage`：
关掉标签页就没了，不会写进 URL、不会写进 localStorage。

密钥框**永远是空的**（已连接的状态只写在框外的提示与 placeholder 上），而且密钥只能是 ASCII：
HTTP 请求头装不下中文与全角符号，页面会在发请求之前把不合法的密钥拦下来。

网关本身不会自行重启：需要重启时页面只会提示，由你自己动手。

## 安全边界

| 内容 | 是否需要密钥 |
| --- | --- |
| 静态壳（HTML/JS/CSS） | 不需要（里面没有任何数据） |
| `/admin/*` 数据接口 | 需要 `Authorization: Bearer <GATEWAY_API_KEY>`，且统一用 POST |
| `/metrics` | 需要 |
| `/v1/*` 数据接口 | 需要管理密钥或任意一把用户级密钥 |

- 网关未配置 `GATEWAY_API_KEY` 时，数据接口一律 `403 {"error":{"code":"admin_disabled"}}`，页面会直接告诉你原因；
- 密钥缺失或错误 → `401`；
- 用户级密钥访问管理接口 → `403 {"error":{"code":"forbidden"}}`；
- **密钥内容永不下发到浏览器**：配置视图只给出它引用的环境变量名，以及那个变量「是否已设置」；
- 用户级密钥明文只在新增时显示一次，SQLite 里只保存摘要，列表只显示可读前缀。

只想暴露转发接口的部署，可以整体关掉前端与配置接口：

```bash
ADMIN_UI_ENABLED=false      # 不提供 /admin/ui（404）
CONFIG_API_ENABLED=false    # 不提供 /admin/config/*
```

## 常见报错

| 页面上的提示 | 原因 | 怎么办 |
| --- | --- | --- |
| `密钥里有不能放进请求头的字符：「…」(U+XXXX)` | 密钥框里混进了中文或全角符号：HTTP 请求头只接受可打印的 ASCII | 清空密钥框，只粘贴 ASCII 密钥 |
| `本标签页里保存的密钥不合法…已清除` | 这个标签页之前存过不合法的密钥（旧版本会把框里的提示文字当成密钥保存） | 按提示重新输入一次密钥，之后所有请求都正常 |
| `无法连接网关：…` | 网关没启动、端口不对，或反代没有转发 `/admin/*` | 核对地址与端口，见 [怎么打开](#怎么打开) |
| `密钥缺失或不正确：请在右上角重新输入 GATEWAY_API_KEY` | 输入的密钥与网关的 `GATEWAY_API_KEY` 不一致 | 重新输入；仍然 401 就核对网关配置 |
| `网关未配置 GATEWAY_API_KEY，管理接口已关闭` | 网关没有设置管理密钥 | 设置 `GATEWAY_API_KEY` 后自行重启 |

> 浏览器原生的 `Failed to read the 'headers' property from 'RequestInit': String contains non ISO-8859-1 code point`
> 属于第一类问题：现在密钥在进入请求头之前就会被检查，页面上直接给出是哪个字符，不会再抛这种看不懂的错误。

## 五个标签页

### 用户密钥

- `GATEWAY_API_KEY` 只用来连接管理台，不要发给普通用户；
- 在这里填写用户标签并点「生成密钥」，新密钥明文只显示这一次，请立即保存；
- 用户密钥只能访问 `/v1/*`，访问任何 `/admin/*` 或 `/metrics` 都会得到 `403`；
- 删除用户后该密钥立即失效，已产生的审计记录保留，历史流量仍然可按用户标签查询；
- 用户标签会写进审计行（`api_user`），在「用量与性能」选择「按用户」即可对比流量。

### 用量与性能

- 顶部卡片：全量请求数，以及**输入 / 输出 / 缓存 tokens**（来自永久保留的日汇总）；
  另附明细范围内的成功率、失败尝试、客户端中断、重试尝试；
- **每日用量**：按 `日期 × 用户` 展示请求数、输入 / 缓存 / 输出 tokens、成功与失败数；
  这张表只累加、不清理，能查到比审计明细更早的历史；
- 趋势图：按小时/天分桶的请求数、P95 耗时、首块耗时；
- 模型榜：按 P95 / 首块 / tokens/s / 故障转移 / 失败 / tokens 排序；
- 聚合明细：按模型、平台、用户、入口、请求的 `model`、结局、错误分类、按天聚合；
- **透传维度汇总**：按 `model`、`model,size`、`day,user,model,size` 等任意维度组合查看永久调用量。

筛选条件：时间范围、聚合维度、排序、曲线粒度、平台、模型名、用户标签。
时间范围默认「全部（保留所有记录）」，聚合维度默认「按天」。

### 审计明细

一次上游尝试一行。可以按时间、结局、平台、模型、用户、请求 ID 过滤，翻页。
**点击任意一行**会展开它所属请求的完整故障转移链：每次尝试的耗时、首块、探测、状态码、错误分类、是否被禁用、`[DONE]` 是否已转发、tokens。

**明细默认保留 30 天**（`AUDIT_RETENTION_DAYS`），更早的行会在启动时与运行中定期清理；
页面默认查询最近 30 天，并明确提示「全量用量在日汇总里永久保留」，避免误以为历史用量丢了。

结局列旁边还有一列 `[DONE]`：`已发完` 表示终止标记已经转发给客户端（客户端随后关闭连接属正常，记 `success`），
`未发完` 才是内容被掐断（记 `aborted`）；筛选区下方直接写着一行结局口径，不用翻文档。

顶部还有一排审计自身的健康指标：库行数、缓冲待写行数、丢弃计数、写库失败计数、保留天数、最近刷盘时间。

### 模型配置

读的是脱敏视图：平台名、`baseUrl`、密钥引用的环境变量名与是否已设置、权重、超时、重试次数、首块/探测超时、黑名单、插件（含是否爬虫模式）、模型条目与它们的覆盖字段。

布局是**分模块折叠**的：每个平台、别名段、`audit` 段、透传路由、新增平台/透传各是一个可折叠区块，默认折叠。
折叠状态下一行摘要就够判断要不要展开，例如：

```text
▸ 平台：example-platform   权重 10 · 120s · 重试 3 · 模型 2 · 爬虫模式
▸ 模型组别名（2）           指向从下拉里挑；整列表覆盖会丢掉附着在这些行上的注释
▸ 审计段（audit）           已开启 · 保留 30 天
```

摘要里还会直接写出「环境变量 `EXAMPLE_PLATFORM_API_KEY` 未设置」「已停用」这类问题。
顶部有「全部展开 / 全部折叠」；写盘、回滚、重载之后的刷新会保留你原本展开着的区块。

展开以后每块里的排版：现状用**两列键值表**（左列字段名、右列取值）而不是竖排；
区块级动作（如「删除平台」）在展开区域的右上角；模型条目的「选择模型」与「删除选中的模型条目」在同一行。
配置页的表格允许换行；列本来就多的表（审计明细、备份列表、模型对比）套在自己的可滚动区域里横向平移，
窄屏时表格上方给一句「左右拖动可以看全」，整页不会被撑出横向滚动条。

取值控件的原则是**能列选项的就不给输入框**（输入框会把长取值截断看不全）：

| 字段类型 | 界面上的控件 |
| --- | --- |
| `true/false` | 下拉：「是（true）/ 否（false）」 |
| 只有有限几种写法（`quota_period`） | 下拉：`hourly / daily / weekly / monthly`，外加「不配置（删掉这一行，回落到上层）」 |
| 数值（`timeout`、`weight`、`retention_days` …） | `type=number` 输入框，带 `min`/`max`/步进，旁边写明「取值范围 1 ~ 3600」 |
| 列表（`blacklist`、别名指向、新增模型条目的覆盖） | 已选内容用**标签**完整显示（可点 × 去掉），新增只从下拉里挑——**页面上没有手填入口**；候选超过 8 个时自动多一个「筛选候选」框（它只缩小下拉，永远不会变成取值），下拉最多放 40 项并写明「共 N 个候选，只列前 40 个，用筛选框缩小范围」 |
| 确实只能手填（`baseUrl`、密钥占位符、`db_path`） | 输入框，并把当前取值回填进去（密钥只回填 `${ENV}` 占位符，永远不会回填真实密钥） |

每个控件里都预填了**当前取值**，模型级覆盖还会写明「这个条目没写，继承平台的 xxx」，不用自己对着空框猜现状。

候选从哪儿来：下拉里的模型 = 配置文件里写着的条目 + `POST /admin/config/models` 给出的**进程里当前正在用的模型**。
爬虫平台的模型是插件灌进来的，`models.yaml` 里根本没有条目，所以那类候选只能问进程；页头「进程里的模型」那一行写明进程当前加载了几个，
一个都没加载时下拉是空的，接口会给出说明（不是报错）。唯一挑不出来的写法是按通配屏蔽（例如 `prefix-*`）：
下拉只列真实条目，那种模式要手改 `models.yaml` 里的那一行，界面上也这样写着。

可以改（页面上有对应控件）：
- 平台字段：`baseUrl`、`apiKey`（写占位符，别写明文密钥）、`weight`、`timeout`、`retry_count`、`connect_timeout`、`first_chunk_timeout`、`stream_probe_timeout`、`quota_period`、`enabled`、`enable_tool_call_conversion`、`blacklist`
- **加模型**：平台区块里「模型条目（N）」小节的第一行「加模型」→ 只有**模型名**要打字 → 需要覆盖就在下一行「字段下拉 → 选/填取值 → 加一项覆盖」逐条加，已选的覆盖显示成带 × 的标签（如 `weight=5`、`enabled=false`）→ 「新增模型条目」。不带覆盖就是全部继承平台级取值；要加多个就多点几次，模型名会留在框里，覆盖每次清空
- 模型级覆盖：先用「选择模型」下拉选中模型，再选字段 → 改取值 → 「加入改动」
- 删除静态模型条目（`remove_model`）
- **别名（模型组的昵称）**：配置页最下方的「模型组别名（N）」区块。已有别名的指向是一排**标签**（完整显示 `平台名|模型名`，不会被输入框截断）＋「选一个加进来…」下拉（候选是 `all` / 整个平台 / 单个模型 / 插件灌进来的模型）＋「清空这一行」，改完点「覆盖别名指向」；**新建别名**用最后一行（占位符写着「别名，例如 cheap」）→ 填别名 + 挑指向 → 「新增别名」。插件运行时灌进来的模型（不在配置文档里）也在候选里，写法是 `平台名|模型名`，没有手填入口
- `audit:` 段字段（`set_audit_field`）
- 新增平台 / 删除平台（`add_platform` / `remove_platform`，改完需要你自行重启）。新增平台那一块里：平台名、`baseUrl`、密钥占位符要打字，**模型条目一次填一个**（填一个点「加一项」，变成带 × 的标签，回车也等于「加一项」），不再写 `model-a, model-b` 这种容易写错的逗号串

只有 CLI 提供、页面上没有的操作：无 —— 10 个补丁操作页面与 CLI 都能用。
（页面里「删除该字段（回落）」= `unset_platform_field` / `unset_model_field`；
「新增模型条目」= `add_model`；「新增别名」与「覆盖别名指向」都是 `set_alias_selectors` —— 别名不存在时后端会把它建出来。）

别名指向写错平台名不会被拒绝，但预演的警告里会写：
`别名 cheap 指向的平台 ghost-platform 不存在，这条指向不会命中任何模型`。
爬虫平台的模型是运行时灌进来的，所以校验只查 selector 的平台段。

页面上改配置的操作顺序：

1. 右上角输入 `GATEWAY_API_KEY` → 连接
2. 「模型配置」标签页里展开目标平台（点摘要行），找到目标区块 → **加入改动**（改动进入待提交清单，可以逐条撤掉）
3. **差异自动出现**：改动一进清单就替你预演一次（只读，不写盘；连着改几条会合成一次）。
   看「改了哪些字段」「配置文件里改动的行」、校验错误与警告、`需要重启` 标记
4. 校验通过就 **应用并写盘** → 后端先备份再原子写盘，并尝试进程内热重载
5. 需要重启时页面只提示，由你自己重启

「重新预演」按钮只是手动再算一次（例如你手改过 `models.yaml` 之后）。
**写盘前页面会核对：预演的必须是当前这一批改动**——清单在预演之后又变过（含撤掉）会自动重算，
所以「预演通过」和「实际写盘的内容」不会不一致。清空改动按钮不会碰磁盘。

### 差异怎么看：颜色与对齐

| 颜色 | 含义 |
| --- | --- |
| 绿 | 新增（原来没有这一行/这个字段） |
| 黄 | 修改（同一行给出原值 → 新值，不会拆成「一删一增」两条） |
| 红 | 删除，或「删掉这一行回落到上层默认」 |

- 颜色口径直接写在差异区顶部，不用翻文档。
- 「待提交的改动」「改了哪些字段」「配置文件里改动的行」三块共用同一套四列栅格
  （**状态 / 位置 / 原 / 新**），所以行与行、块与块都能纵向对得齐；窄屏下位置自己占一行，原值与新值仍然并排。
- 行级差异来自后端的 `diff_rows`（`openai_proxy/config_store/line_diff.py`），类别由后端判定，界面不自己猜。
- 只有取值相同、位置不同的改动也会被标成修改；如果一批改动实际上什么都不改，差异区会直接写「这一批改动不会真的改变文件内容」。

### 备份与回滚

每次写盘前都会自动备份。列表给出文件名、时间、字节、版本、备注，点「回滚到此版本」即可。
回滚前当前内容也会再备份一份，所以**回滚本身也能再回滚**。

这里还有一个「进程内重载配置」按钮：手改过 `models.yaml` 之后不重启进程也能生效。

## 字段字典：这一页本身就是文档

配置页不再只给你字段名。每个能改的字段都有说得清的说明，出现在两个地方：

- **编辑块下面**：选到哪个字段，就换上哪个字段的说明 —— 它控制什么行为、默认值（不配置时发生什么）、
  取值单位、`models.yaml` 里的写法示例、改完是**热重载**还是**需要重启**，以及容易踩的坑。
- **配置页尾部的五个区块**（都默认折叠）：四个字段字典（平台级字段 / 模型级可覆盖字段 / `audit` 段字段 / `passthrough` 段字段）与一个「配置结构说明」。
  字典用**卡片网格**（宽屏多列、窄屏自动减列，不会横向滚动），每张卡片一个字段：字段名 + 生效方式、含义、默认值、取值单位、
  `models.yaml` 写法示例、注意点。结构说明有六段：

| 段落 | 讲什么 |
| --- | --- |
| `models.yaml` 里只有四类东西 | 平台段、`all_aliases`、`audit`、`passthrough`；哪些顶层键不是平台 |
| 模型条目有两种写法 | 字符串写法与对象写法、覆盖字段白名单、合并规则、插件灌入条目与静态条目的先后 |
| 请求里的 `model` 可以有四种写法 | `all` / 平台名 / `平台名\|模型名` / 别名，以及各自的容错方式 |
| 改动什么时候真正生效 | 热重载做了什么、哪些改动必须重启、没有文件监听 |
| 注释会被怎样对待 | 只改取值 / 删条目 / 写法互转 / 整列表覆盖 |
| 并发保护与回滚 | 版本号与 `409`、备份与原子写盘 |

说明只有一份来源：`openai_proxy/config_store/field_docs.py`（单字段）与
`openai_proxy/config_store/config_guide.py`（结构），由 `POST /admin/config/schema` 的
`docs` 与 `sections` 下发。界面不自己编文案，测试也锁住「能改但没解释」的字段不得出现。
命令行给出同一份：`python manage.py config fields`（`--json` 时与接口返回一致）。

字典里写的是**真实的坑**，不是套话，例如：

- `retry_count` 只在请求写成 `平台名|模型名` 时才生效；写 `all` 或只写平台名时每个模型只试一次。
  下限是 1（写 0 会走到没有兜底的重试分支，非流式请求可能变 500）。
- 模型级 `weight` 只有「该平台第一个条目」的值会被采用：平台内部按 `models` 列表顺序尝试，不按权重排序。
- `enable_tool_call_conversion` 写在平台级当前不会被读取，只有写在模型条目的覆盖里才生效。
- `audit:` 段的**每一个**字段都要重启才生效（`audit` 只在启动时应用一次），页面上会逐字段标注。
- `metrics_label_model` 写在 `models.yaml` 里没有运行时效果：真正的开关是环境变量 `METRICS_LABEL_MODEL`。

## 改配置的正确流程

页面刻意把「预演」和「写盘」分成两步，和 CLI 的 `--dry-run` 一样：

1. 在表单里改字段 → 点「加入改动」，改动进入待提交清单（可以撤掉）；
2. 点「预演（看差异）」→ 看到变更清单、**行级 diff**、校验错误与警告、是否需要重启；
3. 预演通过后「应用并写盘」按钮才可点 → 后端先备份再原子写盘，并尝试进程内热重载。

并发保护：请求带 `If-Match: "<version>"`。如果你在编辑期间别人也改了配置，
后端返回 `409`，页面会刷新出最新配置并清空待提交清单，**不会覆盖别人的改动**。

需要重启的情况（`needs_restart=true`）：新增/删除平台、改动 `plugin` 结构。
页面只提示「需要你自行重启服务才会完全生效」，不会自己重启。

爬虫平台（插件带 `scrape_url`）的模型由插件灌入，删除条目会被拒绝，必须改用 `blacklist` 屏蔽。

## 注释会被保留到什么程度

配置是用 ruamel 的 round-trip 模式直改 `models.yaml`，注释尽量保住：

| 改动 | 注释结果 |
| --- | --- |
| 只改取值 | **注释原地不动**（包括行尾注释） |
| 条目写法变化（`- "model-a"` ↔ `- name: "model-a"`） | 该条目附带的注释会被摘掉，并在警告里报告 |
| 删除模型条目 | 该条目的注释一起删掉，其余条目的注释下标自动修正 |
| 整列表覆盖（别名 selector） | 附着在这些行上的注释会丢，警告里会逐条列出「改动后这条注释消失了」 |

写盘前一定会通过序列化自检（结构一致 + 二次往返格式稳定），自检不过就不写盘。

## 关闭前端

```bash
ADMIN_UI_ENABLED=false
```

关掉后 `/admin/ui/` 返回 404，`/admin/*` 数据接口不受影响，仍然可以用 CLI 或 curl 操作。

## 技术构成

```text
web/
  index.html          静态壳：标签页 + 密钥输入
  style.css           样式，深浅色自适应
  API.md              前后端字段契约（改接口必须同步）
  js/
    app.js            入口：标签切换、统一提示
    api.js            请求层：密钥、错误规整
    ui.js             排版小工具：表格、卡片、表单控件
    charts.js         canvas 折线图/柱状图（不依赖任何图表库）
    config_fields.js  配置表单 → 补丁操作
    option_controls.js 取值控件：能列选项的字段一律不给自由输入框
    diff_view.js      待提交清单与差异的排版：状态/位置/原/新 四列对齐，新增绿 修改黄 删除红
    view_usage.js     用量与性能
    view_audit.js     审计明细
    view_config.js    模型配置（改动一进清单就自动预演，差异实时显示）
    view_backups.js   备份与回滚
```

没有构建步骤、没有外部 CDN、没有第三方依赖：改完文件刷新页面即可。

挂载逻辑在 `openai_proxy/service.py` 的 `_mount_admin_ui()`，静态目录由
`openai_proxy/admin_ui.py` 的 `AdminUiStatic` 提供：响应带 `Cache-Control: no-cache`，
浏览器每次都用之前都会回源确认版本（未变化的文件走 304），不会把旧版前端缓存住。
